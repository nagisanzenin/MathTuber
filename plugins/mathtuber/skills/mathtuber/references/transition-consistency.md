# Keep claims consistent while inputs change

A mathematically correct before-frame and after-frame can still create a false explanation between them. Review the transition as a sequence of claims, including labels that stay on screen while another object changes.

An observed nearest-neighbor scene converted a horizontal coordinate from 2 to 200 but left the old “raw distance → A” result visible until a later narration cue. The geometry stayed fixed intentionally, with a note about converted labels. That note did not make the stale result correct. The repair removes the old decision at the conversion cue, then reveals the recomputed decision when explained. When returning briefly to the original squared distances, the converted decision is hidden again.

For each changed input, identify dependent visible quantities: labels, totals, arrows, classifications, highlighted winners and conclusions. Choose one of these explicit presentations:

- Update dependent values consistently with the changing state.
- Hide the dependent answer while recomputing it, then reveal the new answer.
- Keep an explicitly labeled before/after comparison with each result attached to its own inputs.

A causal demonstration may show an input movement followed by an output movement. Make the old and new states identifiable, and avoid leaving an unlabeled old answer under a new equation. For an iterative algorithm, retain the old pair until both new values are computed; do not accidentally use one newly updated value in the second calculation.

Inspect samples immediately before the change, during movement, after the changed input, and at the new conclusion. Include a return to an earlier state if the narration compares before and after. Check against an independent calculation. Existing cue samples are useful but a sample several seconds after every cue can miss a brief contradiction; add targeted samples when needed.

This is a production repair derived from observed scenes. It is not evidence that a viewer learned more, or that every transient state is correct. Re-render and inspect the current export before accepting the repaired film.
