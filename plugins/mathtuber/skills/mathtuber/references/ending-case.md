# An ending the viewer can use

When the ending repeats a static conclusion, consider one changed case using the same objects. This is an optional editorial technique, not a proven Shorts-retention rule.

Write a small ending plan in the project assets:

```json
{
  "original_case": "The demonstrated input and its result",
  "changed_condition": "One meaningful change",
  "viewer_inference": "A modest question answerable from this film",
  "resolution": "Visible result and why it follows",
  "prerequisite": "What the viewer still needs to understand"
}
```

Invite noticing without a countdown, grading or claims about intelligence. Keep necessary quantities visible. Give the result before the film ends and ensure its labels agree with the changed inputs. A transfer case should exercise the central idea, not introduce a second unexplained theorem.

Inspect the current final fifteen seconds. Record whether the changed case and its answer can be followed, including what still feels static or abstract. Do not equate another animation with another insight. A film already ending with a clear consequence does not need an additional question. Learning, retention and aesthetic benefit require audience evidence.
