# Learn from an animation decision

Use these examples when a render is technically valid but the mathematical inference is unclear. They are production observations, not measured learning outcomes or mandatory visual templates.

| Situation | Decision and reason | How to check it |
| --- | --- | --- |
| Array capacity doubles | Show the destination storage and copies before removing the old allocation. Otherwise a pulse or bounce can suggest that nothing moved. | Follow the same numbered items across the move; count writes separately from copies. |
| A percentage base changes | Keep the original reference level visible, use a fixed-width vessel, and state the current base. | A20% decrease leaves80;20% of80 adds16. Height ratios and labels must agree. |
| Overlapping lists are merged | Pair the duplicate identifiers, then remove only the extra copies. | People in both groups remain in the union; the final count is8, not5. |
| The example changes | Hide the previous result before introducing a new participant or changed score; reveal the recomputed answer after the operation. | Inspect the transition itself, not just the opening and final still. |
| Randomized answers are aggregated | Label arithmetic as expected counts and keep finite-sample uncertainty explicit. |80 true yes and20 true no yield65 expected yes under the stated mechanism, not a guaranteed observed count. |

A source-level `remove` call is not evidence that the unwanted label is absent in the encoded frame. In the applications production, short explicit fades repaired visible old labels during changed cases. The renderer-level cause was not isolated; do not generalize this observation into a claim that `remove` is broken. Re-render and inspect the affected timestamps.

An editorial explanation should name: the intended viewer inference, the persistent objects that support it, the changed condition, and one remaining weakness. For example, the softmax bar makes invariance visible but does not itself derive exponential cancellation. A stronger model or a simpler explanation may still be needed when the prerequisite reasoning is too demanding.

Retrieve [transition consistency](transition-consistency.md) for stale answers and [ending cases](ending-case.md) for an optional final inference. Editable applications live in the repository examples; the installed plugin does not require those examples to be present.
